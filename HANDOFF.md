# TorBox Drop

Repository source controls implementation. ProjectStatus/projects/torbox/STATUS.md controls readiness.

## Current benchmark
Version 2.1.0 adds a corrected native download path, visible device download preparation/progress/failure, visible added/cache dates and ages, ready-row folder entry, and a standalone web explorer. Native source retains the package app.jabs.torboxdrop and the existing Drive, Delete, share-confirmation and encrypted-token architecture. The existing private signing key has been recovered locally for an in-place update. Never put it or its credentials into Git.

The web client is generated by `node web/build.mjs` from web/src and web/index.template.html. It is session-only, with no browser storage or cookies. The Node relay in relay/server.mjs only forwards an allowlist of TorBox API operations, retaining a key for the duration of that request. It never downloads or proxies file/media bodies. Direct browser saving streams chunks to disk where supported; the browser download fallback explicitly discloses TorBox links containing the account key. Copy/open/share refuse those links.

## Hosting constraint
Live OPTIONS checks on 2026-10-01 proved TorBox rejects GitHub Pages, localhost and null origins; the official TorBox origin is allowed. Therefore a static GitHub page alone cannot work. render.yaml prepares one free, stateless `torbox-drop-api` service. No database, paid tier or video relay is used. Deployment awaits the Render connector's required confirmation of `My Workspace` (tea-dakujgmk1f9s73d2v8ng). Do not select a workspace or claim the backend is live until the user confirms. This is separate from the Web Player; do not modify or redeploy that project as part of Drop.

The frontend publication target is Misc/TorboxDrop/index.html, because Misc's existing GitHub Pages publication is enabled. Source and versioned APK remain in this repository. The HTML's torbox-api meta value must match the actual service URL returned after creation, then regenerate and synchronize the published copy.

## Do not break
- Native Google Drive destinations, account switching, share confirmation, delete markers and cached state.
- Exact TorBox file IDs, no inferred file index.
- Readiness means download_finished AND download_present.
- cached_at is labeled Cached, never falsely described as the account completion date; unknown dates remain unknown.
- Never send a raw API key to an unrelated download host or copy/share it without consent. Android DownloadManager receives only validated device-download URLs.
- Web keys and account/file lists never enter localStorage, sessionStorage, cookies, URL state, analytics, or a database. Browser/Android download history may retain direct storage URLs.
- Mutations are single-item only; do not automatically retry an uncertain mutation.
